## 1. 이번 세션에서 해결한 문제

### 1-1. `0198D0` 등 ETF명 깨짐 버그 (완전 해결)

**증상:** `0198D0`(1Q SK하이닉스선물단일종목레버리지) 등 일부 종목의 ETF명이
`ticker\n0198D0 ...\n0198D0 ...` 형태의 지저분한 다중행 텍스트로 반환됨.

**원인 규명 과정:**
1. pykrx 소스코드(`EtxTicker` 클래스) 추적 → 중복 인덱스에서 `.loc[]` 조회 시
   `pandas.Series`가 반환되고, 이를 `str()` 변환하면 증상과 동일한 텍스트가
   나옴을 로컬 재현으로 확인.
2. KRX 공식 API(`getJsonData.cmd`, bld: `MDCSTAT04601`)를 브라우저 개발자도구로
   직접 캡처해 원본 데이터를 대조 → **KRX 원본 데이터 자체는 정상**(중복 없음),
   문제는 pykrx가 ETF+ETN+ELW 세 카테고리를 병합하는 과정에서 발생한 것으로 확정.
3. 2026-05-27 상장된 단일종목 레버리지/인버스 ETF·ETN **18개 종목**(SK하이닉스,
   삼성전자 대상)이 KRX 데이터에서 ELW 목록에도 중복 등재되어 있었음
   (KRX 원본 데이터 결함, pykrx 라이브러리 버그 아님).

**해결:** `get_etf_ticker_name_safe()` 함수 신규 작성. 중복 발생 시 ETF/ETN
카테고리를 ELW보다 우선 선택하도록 처리. `app.py`에 반영 완료.

### 1-2. `489010`(PLUS 글로벌AI인프라) 등 종목명 결측 (자연 결측으로 확정)

5개의 독립적인 소스에서 전부 부재를 확인:
- pykrx (`EtxTicker`, `get_etf_ticker_list`)
- KRX 정보데이터시스템 "전종목 기본정보"(`MDCSTAT04601`) 다운로드
- KRX 정보데이터시스템 "전종목 시세"(`MDCSTAT04301`) 다운로드
- funetf.co.kr (삼성자산운용 운영 서비스) — 여기서는 정상 거래 종목으로 확인됨
- KIS(한국투자증권) Open API 현재가 조회

funetf에서는 실시간 거래되는 것으로 보였으나, 순자산 30억원 규모의 초소형
펀드였던 점을 고려하면 최소 유지 기준 미달로 상장폐지 절차가 진행 중이었을
가능성이 높음(공식 상장정보 목록에서는 빠졌지만 거래소 매매 자체는 폐지
직전까지 지속되는 경우가 흔함). **결론: 자연 결측으로 처리, 코드 수정 불필요.**

### KRX 데이터 이용 정책 확인 (중요)

KRX 공식 안내([data.krx.co.kr](https://data.krx.co.kr)) 확인 결과, 개인투자자의
시세정보 이용은 **"단순 참고 목적"만 무상 허용**되며, 프로그램을 통한 자동
수집·재배포·재구성은 별도 계약(코스콤 등)이 필요함이 명시되어 있음. 이에 따라
`data.krx.co.kr`의 `getJsonData.cmd` API를 코드에서 직접 호출하는 방식은
**향후에도 사용하지 않기로 결정**. (참고로 세션 중 이 방식을 시도했으나,
2026-01-27부터 KRX 정보데이터시스템 자체가 로그인 필수로 전환되어 있어
익명 세션으로는 "LOGOUT" 응답만 돌아와 기술적으로도 불가능했음.)

**결론: 국내 ETF 시가총액은 KIS(한국투자증권) Open API가 유일한 실질적이고
정책상 적합한 경로.**

## 3. KIS(한국투자증권) Open API 연동

### 3-1. 인증 체계
- 실전투자용 App Key / App Secret 발급받아 사용 (매매가 아닌 시세 조회 전용이라
  실전 계좌 사용에 문제없음, 계좌 잔고 없어 리스크 없음)
- **"접근토큰은 1일 1회 발급 원칙"** — KIS로부터 실제 알림톡 안내를 받아 확인.
  파일 기반 캐싱(`get_kis_access_token_cached()`)으로 23시간 이내 재발급 방지 처리.
- App Key/Secret은 `.env` 파일에 저장(`KIS_APP_KEY`, `KIS_APP_SECRET`),
  `.env.example`에는 항목명만 추가(실제 값 없음), `.gitignore`로 `.env`
  Git 추적 제외 확인.

### 3-2. 시가총액 조회 함수
`fetch_kis_market_caps()` — '국내주식 현재가 시세' API(`FHKST01010100`)의
`hts_avls` 필드가 이미 억원 단위로 계산된 시가총액이라 별도 계산 불필요.

### 3-3. 알려진 한계 (다음 세션 과제)
- **속도 문제:** 1161개 종목을 순차 조회 시 15~20분 이상 소요. `ThreadPoolExecutor`
  기반 병렬 처리(초당 8건 제한)를 적용했으나 로컬 테스트에서 체감 개선 효과가
  거의 없었음 — 원인 미규명, 추가 조사 필요.
- **일시적 실패:** 개별 종목 단위로 간헐적 실패가 발생(전체의 약 2%),
  현재는 재시도 로직 없이 결측 처리됨. 필요시 재시도 로직 추가 여지 있음.

## 6. 운영 편의성 개선

- **바탕화면 실행 아이콘 생성:** `.bat` 파일로 venv 활성화 + `streamlit run app.py`를
  한 번에 실행하도록 구성. VS Code 실행 없이 더블클릭만으로 앱 구동 가능.
  ```bat
  @echo off
  cd /d C:\Users\hslee\etf-holdings
  call venv\Scripts\activate
  streamlit run app.py
  pause
  ```
- **모바일 접근성 검토(참고용):** 이번 앱(배치 조회형)은 모바일에 최적화할
  필요성이 낮다고 판단, 별도 작업 안 함. 단, 같은 와이파이망에서
  `--server.address=0.0.0.0` 옵션으로 접속하거나, Streamlit Community Cloud로
  배포하면 모바일 접근 가능(배포 시 `.env` 대신 Streamlit Secrets 별도 설정 필요).
  향후 "수시 조회형" 프로젝트(예: 종목 분석)를 만들 경우, 설계 단계부터
  모바일 사용을 전제로 다르게 설계해야 함을 확인.
